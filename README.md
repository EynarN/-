# Linux /proc Monitor

Два Bash-скрипта для мониторинга Linux через виртуальную файловую систему `/proc`:

- **`proc_monitor.sh`** — собирает сведения о запущенных процессах, выводит их таблицей и записывает в лог только **новые** процессы;
- **`input_monitor.sh`** — показывает подключённые устройства ввода, а в фоновом режиме **сигнализирует о новых подключениях**.

Оба скрипта запускаются по расписанию через cron. Никаких зависимостей, кроме Bash и стандартных утилит.

## Требования

- Linux с доступной `/proc`
- Bash 4.0+ (нужны ассоциативные массивы)
- `awk`, `readlink`, `tr`, `sort` — стандартные утилиты coreutils
- `cron` — для запуска по расписанию
- Права root — для чтения `/proc/N/exe`, `/proc/N/cwd`, `/proc/N/fd` процессов других пользователей

Необязательно: `logger` (запись в системный журнал) и `notify-send` (всплывающие уведомления в графической среде).

## proc_monitor.sh — мониторинг процессов

### Использование

```bash
sudo ./proc_monitor.sh        # таблица процессов + запись новых в лог
sudo ./proc_monitor.sh -q     # тихий режим (для cron): только запись в лог
```

### Собираемые данные

| Столбец   | Источник            | Описание                                   |
|-----------|---------------------|--------------------------------------------|
| `PID`     | `/proc/[0-9]*`      | номер директории процесса                  |
| `Name`    | `/proc/N/exe`       | имя исполняемого файла                     |
| `State`   | `/proc/N/status`    | состояние: R, S, D, Z, I…                  |
| `FDs`     | `/proc/N/fd`        | количество открытых файловых дескрипторов  |
| `CWD`     | `/proc/N/cwd`       | текущая рабочая директория                 |
| `Cmdline` | `/proc/N/cmdline`   | командная строка запуска                   |

У потоков ядра нет исполняемого файла, поэтому их имя берётся из `/proc/N/comm` и выводится в квадратных скобках, например `[kthreadd]`. Недоступные значения выводятся как `-`.

### Пример вывода

```
PID     Name                 State FDs   CWD                          Cmdline
--------------------------------------------------------------------------------------------------------------
1       systemd              S     98    /                            /sbin/init splash
2       [kthreadd]           S     0     /                            -
...
4217    sleep                S     3     /home/user                   sleep 40

Всего процессов: 65
Новых процессов: 3. Лог: /var/log/proc_monitor/proc_monitor.log
```

## input_monitor.sh — мониторинг устройств ввода

### Использование

```bash
sudo ./input_monitor.sh           # список устройств + запись новых в лог
sudo ./input_monitor.sh -q        # тихий режим (для cron)
sudo ./input_monitor.sh -d 5      # фоновый режим, проверка каждые 5 секунд
```

Запуск в фоне и остановка:

```bash
nohup sudo ./input_monitor.sh -d 5 > /dev/null 2>&1 &
sudo kill <PID>
```

### Собираемые данные

Скрипт разбирает `/proc/bus/input/devices` по столбцам:

| Столбец    | Строка-источник | Описание                                |
|------------|-----------------|-----------------------------------------|
| `Bus`      | `I: Bus=`       | тип шины (`0003` — USB, `0011` — i8042) |
| `Vendor`   | `I: Vendor=`    | ID производителя                        |
| `Product`  | `I: Product=`   | ID устройства                           |
| `Version`  | `I: Version=`   | версия                                  |
| `Name`     | `N: Name=`      | название устройства                     |
| `Phys`     | `P: Phys=`      | физический путь подключения             |
| `Handlers` | `H: Handlers=`  | обработчики (`kbd`, `mouse0`, `event*`) |

### Пример вывода

```
Bus  Vendor Product Version Name                               Phys                       Handlers
-------------------------------------------------------------------------------------------------------------------
0019 0000   0001    0000    Power Button                       LNXPWRBN/button/input0     kbd event0
0011 0001   0001    ab41    AT Translated Set 2 keyboard       isa0060/serio0/input0      sysrq kbd event1 leds

Всего устройств: 2
```

### Сигнализация о новых устройствах

В фоновом режиме (`-d`) при появлении нового устройства скрипт:

- подаёт звуковой сигнал терминала (`\a`);
- выводит сообщение в stderr;
- пишет в системный журнал: `journalctl -t input_monitor`;
- показывает всплывающее уведомление через `notify-send` (если запущена графическая среда).

## Запуск по расписанию (cron)

Файл `monitoring.cron`:

```cron
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

# Каждые 5 минут — новые процессы
*/5 * * * * /usr/local/bin/proc_monitor.sh -q >> /var/log/proc_monitor/cron.log 2>&1

# Каждую минуту — новые устройства ввода
* * * * * /usr/local/bin/input_monitor.sh -q >> /var/log/input_monitor/cron.log 2>&1
```

Установка в crontab root:

```bash
sudo crontab monitoring.cron
sudo crontab -l
```

> ⚠️ `crontab monitoring.cron` **заменяет** текущий crontab пользователя. Если в нём уже есть задания, добавьте строки вручную через `sudo crontab -e`.

## Логи

| Скрипт              | Лог                                         | Файл состояния                               |
|---------------------|---------------------------------------------|----------------------------------------------|
| `proc_monitor.sh`   | `/var/log/proc_monitor/proc_monitor.log`    | `/var/log/proc_monitor/known_processes.state` |
| `input_monitor.sh`  | `/var/log/input_monitor/input_monitor.log`  | `/var/log/input_monitor/known_devices.state`  |

Если нет прав на запись в `/var/log`, используется `~/.local/state/<имя_скрипта>/`. Каталог можно переопределить переменной `LOG_DIR`:

```bash
LOG_DIR=/tmp/mylogs ./proc_monitor.sh
```

Каждый запуск добавляет в лог строку с датой и временем, затем — **только новые** записи. Старые процессы и устройства повторно не заносятся.

```
=== 2026-10-04 09:52:45 запуск proc_monitor: процессов 65, новых 3 ===
  PID=4217    Name=sleep   State=S FDs=3 CWD=/home/user Cmd=sleep 40
  PID=4219    Name=bash    State=S FDs=5 CWD=/home/user Cmd=bash ./proc_monitor.sh
```

```
=== 2026-10-04 09:52:28 запуск input_monitor: устройств 3, новых 1 ===
  Name="Logitech USB Receiver" Bus=0003 Vendor=046d Product=c52b Handlers=mouse0 event7 Sysfs=/devices/.../input/input7
```

Полезные команды:

```bash
sudo tail -f /var/log/proc_monitor/proc_monitor.log      # следить за логом
sudo grep '^===' /var/log/input_monitor/input_monitor.log # только время запусков
```

## Как это работает

### Как определяются «новые» записи

После каждого запуска скрипт сохраняет список текущих записей в файл состояния. При следующем запуске этот список загружается в ассоциативный массив, и в лог попадает только то, чего в нём нет.

- **Процессы** идентифицируются парой `PID:starttime`, где `starttime` — 22-е поле `/proc/N/stat` (время старта в тиках с момента загрузки). Одного PID недостаточно: номера переиспользуются, и новый процесс с освободившимся PID иначе был бы принят за старый.
- **Устройства** идентифицируются путём в sysfs (`.../input/inputN`). При каждом подключении ядро присваивает новый номер `inputN`, поэтому переподключение того же устройства тоже фиксируется.

При первом запуске (файла состояния ещё нет) в лог записывается весь исходный список с соответствующей пометкой.

### Разбор /proc/bus/input/devices

Файл состоит из блоков, разделённых пустой строкой. Цикл `while read` читает его построчно, `case` определяет тип строки по префиксу (`I:`, `N:`, `P:`, `S:`, `H:`), а строка `I:` дополнительно разбивается на пары `ключ=значение`. Пустая строка завершает блок, и устройство сохраняется в массивы.

### Сброс состояния

Чтобы начать мониторинг с нуля, удалите файл состояния:

```bash
sudo rm /var/log/proc_monitor/known_processes.state
sudo rm /var/log/input_monitor/known_devices.state
```
